# Viewer

Shows a component's source with the analyzer's findings drawn over it.

```sh
pnpm --filter bippy-analyzer viewer
```

Open http://localhost:3200/ to see the first of the five demos, and switch between them from the file name in the toolbar. Each is a fixture from the analyzer's tests, and each has three routes: `/counter` shows the code, `/counter/diagram` the decision tree and `/counter/json` the analyzer's own output. The legend on the right follows the component under the pointer: hover a line or a token and it switches, and it stays on the last one you touched. It starts on the component with the most states.

The Diagram tab collapses each component to its declaration line and draws a decision tree per state region: a chip per condition, a card per state with what it renders, and an edge per transition labeled with the action. An action that leaves the state unchanged loops back into its card. The JSON tab shows the analyzer's own output for the file. The legend is a sidebar listing every component in the file as a collapsible panel; the component under the pointer opens, is marked with a bar and scrolls into view when it is out of sight, and any panel can be opened or closed by hand; opening one scrolls the code or the diagram to that component. The sidebar collapses with its toolbar button or Cmd+B, opens as a sheet on phones, and stays collapsed in JSON mode.

Every state variable gets a color. In the source, its declaration, the calls that set it, the conditions that read it and the handlers that set it share that color. A dashed arrow curves from each setter call up to the declaration, and a solid arrow from the declaration down to each condition that reads it. Hovering anything lights its whole causal chain and dims the rest of the code and the legend; the diagram never dims. The right side uses MDP terms: the state variables, the states with their conditions and what they render, and the actions, each with the variables it sets and the transitions `S1 → S2` it causes, in the same colors.

The code is rendered by `@pierre/diffs` and highlighted by its Highlights backend, a WebAssembly lexer from `@pierre/highlights`. The overlay measures each token inside its shadow root, by the `data-line` cell for the line and a text range for the columns, so it follows wrapping and resizing, and a token that wraps gets a mark per row. The shell loads the highlighter as soon as it mounts, so the code is ready by the time a demo is opened; until then a pane shows a spinner.

The viewer is its own workspace package, `bippy-analyzer-viewer`, a Next.js 16 app under `viewer/`. The analyzer never runs in the app: `pnpm generate` runs `generate/generate.ts` with tsx against TypeScript 7, analyzes the five demos and writes `src/generated/demos.json`, which is committed. `generate/view-model.ts` turns the analyzer's output into what the page needs and `generate/code-graph.ts` finds where each identifier sits in the text with Babel. `pnpm dev` regenerates first. To look at any other file while developing, put its path, relative to the analyzer package, in the URL: http://localhost:3200/f/tests/fixtures/symbolic-tree/src/chains.tsx, with `/diagram` or `/json` after it for the other views. The dev server analyzes the file on request with the same generator, caches the result until the file changes, and answers 404 in production. The app validates the JSON with zod in `src/server/demos.ts` and prerenders every route from it with `generateStaticParams`, so the deployed site is static pages and nothing else. The toolbar's menu links to each demo with `next/link` and keeps the current tab, and the mode tabs prefetch the other two routes of the open demo. Inter loads through `next/font` from the `@fontsource-variable/inter` file and Geist Mono from the `geist` package, which the code pane picks up through Pierre's `--diffs-font-family` variable. React Compiler is on and the dev indicators are off. The client is a `Viewer` compound component, `Viewer.Toolbar`, `Viewer.Source`, `Viewer.Legend` and `Viewer.Status`, over a context that holds the demo, the mode, the colors and the hovered token.

The Vercel project builds from `packages/bippy-analyzer/viewer` with `vercel.json` installing only this package.
