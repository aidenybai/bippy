# Differential test findings

The differential suites execute more than 36,700 small programs against both the analyzer and native JavaScript. Seeds are fixed; failures include the seed, case number, complete function body, native result, and analyzer result. Programs use local state, bounded loops, and deterministic operations.

Concrete checks use an isolated Node VM as the reference and compare primitive results with `Object.is`, preserving `NaN`, signed zero, and `undefined`. Callback traces expose effects that a return-value-only assertion would miss.

Microtask programs return a snapshot function. The VM drains its native promise jobs with `microtaskMode: "afterEvaluate"` before the snapshot is read; the analyzer drains its modeled queue before reading the same snapshot. No sleeps are used. The reference implements `queueMicrotask` through native promise reactions for non-throwing callbacks only; host reporting of exceptions from `queueMicrotask` is outside this campaign.

Symbolic checks execute all four combinations of two boolean inputs natively, then compare the analyzer's **enumerated rendered states**, not flattened raw branch alternatives. The latter can contain paths that predicate constraints correctly exclude. Every enumerated assignment must also survive pinned replay, without sampling or correction.

The collection journal campaign adds 10,000 transitions across Map, Set, WeakMap, and WeakSet models. Native Map snapshots provide the oracle for writes, deletion, clear, checkpoint restoration, and identical-path joins. Retained snapshots must preserve object identity, values, membership, and insertion order after subsequent mutations.

The [coverage ledger](./differential-coverage.md) records the determinism contract, finite matrices, remaining axes, and reproducible normal/shuffled test commands. These totals are not a claim of complete JavaScript coverage. Earlier inventory runs passed normal order and fixed-seed test/file shuffling (424242), with identical test-name/status multisets. Current evidence comes from the [compatibility coverage commands](../docs/compatibility-coverage.md).

The sections below preserve historical investigation batches. Statements that a batch included no evaluator fixes do not describe the current working tree. Array-copy isolation, guarded joins/distribution, finite cursor isolation, explicit Date fork isolation, finite descriptor/entry selection, inherited-property lookup, string iteration, and Boolean provenance have since received bounded fixes. The compatibility report remains red; these are bounded improvements, not complete language support.

## How known defects are tracked

Use `pnpm --filter bippy-analyzer compatibility:report` after a fresh coverage run for current assertion and explicit-defect counts. The report includes precision-gap labels and distinguishes ordinary passes from expected defects. A passing overall run does not mean those defects are fixed.

Known-divergence guards accept only a typed `DifferentialMismatch` between a successfully executed native reference and the analyzer result. They replace broad `it.fails` markers, which could mistakenly count syntax errors, setup failures, or new evaluator crashes as expected failures. The known `map` crash separately checks the evaluator-crash wrapper and its specific TypeError cause. Three state-enumeration crash guards require their exact error name and undecided-predicate message.

Recorded concrete mismatch guards use `checkKnownDifferentialWitnesses`: every requested case must reproduce both its recorded native result and its exact analyzer result. A different wrong value, a precision regression, a changed native reference, or one corrected case in a still-failing batch now fails those guards. Existing guards without recorded witnesses continue to check the mismatch class only.

A corrected native match makes its guard fail. Replace that guard with `checkDifferentialCases` or `checkSymbolicCases` when fixing the defect; do not change the reference to the incorrect analyzer behavior.

## Promise and execution-isolation findings

`promise-differential.test.ts` passes 250 seeded races combining pending promises, rejection, duplicate settlement, adoption, `Promise.all`, `finally`, and interleaved microtask observations. Non-callable handlers, self-resolution, input ordering, and empty `Promise.all` have separate passing controls.

Twelve known-divergence cases show that custom thenables are not assimilated correctly:

- `Promise.resolve` skips the `then` getter and its invocation, including a getter that throws. Native `get|sync|getter` becomes analyzer `sync|wrong` in the throwing-getter case.
- Resolving, rejecting, repeated callbacks, and throws before/after resolution are not given native effects and settlement outcomes.
- Constructor resolution, handler returns, `await`, `Promise.all`, and `finally` also omit thenable effects. A thenable returned from `finally` is skipped even when the final fulfillment value happens to match.

`run-isolation-differential.test.ts` checks 1,600 calls across 40 renders sharing parsed module records. Mutations must persist within each run but reset between runs, including module counters, cyclic objects, retained array aliases, replacement, Map order, and writes before a caught throw.

`promise-run-isolation-differential.test.ts` alternates 15 deliberately aborted runs with 15 completed runs over the shared graph. The next run must not inherit abandoned microtasks or settled promise state. Completed runs compare reaction snapshots against native JavaScript; aborts must reject with the exact injected error. Both isolation campaigns pass.
